# PogueDigitalSolutions.com

Static site for Pogue Digital Solutions, LLC. Deployed on Cloudflare Pages from the `main` branch.

- Pages are generated by the scripts in `build/` (shared header, footer, and metadata live in `build/parts.py`). Edit the script for a page, then run `python3 build/build_all.py` from the repo root and commit the regenerated files. That one command builds every page, rewrites links to clean URLs, and regenerates `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt`, and `blog/feed.xml`.
- **Publishing order (standing rule):** every article goes live on this site first, then gets copied to LinkedIn, Medium, Substack, and anywhere else. Every copy links back to the post here. The build writes a ready-to-paste footer for each post to `build/crosspost/<slug>.md`. An optional `source:` line in the front matter holds the LinkedIn copy's URL; the page shows it as "also appears on LinkedIn," never as the original.
- Blog posts are Markdown in `build/articles/`. Add a file with the same front matter as the others and rebuild. Start each post with a `**The short answer:**` paragraph. An optional final `## Frequently Asked Questions` section with `### Question` subheads becomes an accordion plus FAQPage schema.
- **Print view:** every post also builds a paper-ready copy at `/blog/print/<slug>` (linked as "Print this article" in each post's byline). The template is `build/print_view.py`; edit `PRINT_CSS` there to restyle every print page at once. Print pages are noindex with a canonical to the article, so they stay out of the sitemap. Ctrl+P on the regular article page also prints cleanly (print rules at the end of `css/styles.css`).
- Preview locally with clean URLs: `python3 build/serve.py` then open http://127.0.0.1:8787.
- `_redirects` and `_headers` are Cloudflare Pages config. `404.html` is served automatically for missing routes.
- Clean URLs (`/about` for `about.html`) are on by default in Cloudflare Pages.
- **Amazon link clicks (cookie-free):** `js/site.js` sends each click on an Amazon link to `/api/click` (`functions/api/click.js`), which stores only the page, the product ID (ASIN or amzn.to code), the tracking ID, and the date in the `link_clicks` table of the `COMMENTS_DB` D1 database. The private report is `/clicks-admin` (unlocks with `ADMIN_KEY`). Book names on the report come from the link text in `build/articles/*.md`. Create the table once with `npx wrangler d1 execute pds-comments --remote --file db/schema.sql`.
